# 本人訴訟フォルダ構成の前提

HOUHI は、本人訴訟の利用者が、裁判所・期日・提出主体ごとに資料を手元で整理している前提で動く。利用者は HOUHI の内部コマンドや管理形式を知らなくてもよく、エージェントと HOUHI がフォルダ名・ファイル名・OCR Markdown から状況を読み取って補助する。

`00-訴訟管理/` は、コーディングエージェントや HOUHI が索引、作業メモ、整理計画、確認事項などを置くための管理領域である。裁判所に提出する書面や、人間が読む提出資料は、原則として日付ごとのフォルダに置く。

AI エージェントによる仮想チームを使う場合の担当者構成、担当別フォルダ、`AGENTS.override.md` の扱いは、[仮想チーム構成.md](%E4%BB%AE%E6%83%B3%E3%83%81%E3%83%BC%E3%83%A0%E6%A7%8B%E6%88%90.md) を参照する。

## 典型例

```text
2026-03-02-地方裁判所-損害賠償請求事件/
├─ 00-訴訟管理/
├─ 2026-03-02-訴状/
├─ 2026-05-26-第1回口頭弁論/
│  └─ 被告/
│     └─ 乙号証/
│        ├─ 乙1_2025-08-07_反訳書.pdf
│        └─ 乙1_2025-08-07_反訳書.md
├─ 2026-07-07-第2回口頭弁論/
│  └─ 原告/
│     ├─ 2026-06-19_答弁書_反論整理メモ.md
│     ├─ 2026-06-25_準備書面1.md
│     ├─ 2026-06-25_準備書面1.pdf
│     ├─ 2026-06-25_送付書.md
│     └─ 2026-06-25_送付書.pdf
```

## 読み取り方

- ルートフォルダ名は、提訴日・裁判所・相手方名又は事件名を含むことが多い。ただし、これだけで事件名・当事者・裁判所を断定しない。
- `YYYY-MM-DD-訴状`、`YYYY-MM-DD-第1回口頭弁論` のようなフォルダは、提出日又は期日単位のまとまりとして扱う。
- 裁判所提出用の書面、送付書、証拠説明書、反訳書、提出版 PDF など、人間が読む資料は日付ごとのフォルダを主な所在として扱う。
- `00-訴訟管理/` はエージェント作業用の管理領域として扱い、裁判所提出書面そのものの置き場とはみなさない。
- `原告/`、`被告/` は、その階層にある書面や証拠を提出・作成した側の目安として扱う。
- `甲号証/`、`乙号証/` は証拠種別の目安として扱い、ファイル名先頭の `甲1`、`乙1`、`甲3-1` などから証拠番号候補を読む。
- 同じ基礎名の `.md` と `.pdf` が並ぶ場合、`.md` は起案元又は OCR 結果、`.pdf` は提出版・原本写し・変換結果の候補として扱う。
- ファイル名・フォルダ名から得た日付、当事者、証拠番号、書面種別は候補である。提出書面の本文、OCR Markdown、証拠説明書、送付書などで確認できない事項は `【要確認】` とする。

## HOUHI とエージェントの扱い

- HOUHI は、このような利用者作成フォルダを壊さず、`AGENTS.md`、`CLAUDE.md`、`CASE_INDEX.md`、`.houhi/manifest.json` などの補助ファイルを追加・更新する。
- HOUHI が内部管理用に `00_事件管理/` などを作る場合も、既存の `00-訴訟管理/` を上書き・統合しない。管理領域が複数あるときは、それぞれの役割を記録してから使う。
- PDF、画像、Word、ODT、PowerPoint など本文検索できない資料は、OCR Markdown が存在するか確認する。OCR、文書ごとの分割・結合が必要な場合は [`mimi-ocr`](https://github.com/mimidesunya/mimi-ocr) を使う。`mimi-ocr` が使えない場合は、利用者にセットアップを促す。
- 外部 AI OCR に内容を送る可能性がある場合は必ず事前に説明し、明示の承認を得る。
- フォルダ整理を依頼された場合は、OCR Markdown と既存パスから判断し、必要なフォルダ作成、文書分割・結合、リネーム、移動を行う。元ファイルの移動・改名は、利用者の明示承認後にだけ実行する。
- 提出用 PDF の作成、号証スタンプ、証拠 PDF の結合、FAX 向け PDF 化は [`HOUHI`](https://github.com/mimidesunya/houhi) を使う。HOUHI が使えない場合は、利用者に HOUHI のセットアップを促す。
- MIMI OCR Markdown は、メタデータ、ページ境界、判読不能表記、出力規約を保持する。正規化、要約、手作業分割で代替しない。
