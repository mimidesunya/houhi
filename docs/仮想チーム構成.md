# 仮想チーム構成

この文書は、訴訟フォルダで AI エージェントによる仮想チームを結成して作業するときの共通指示である。Codex、Claude Code、Grok Build CLI などのコーディングエージェントで作業する場合も、AI アーカイブを ChatGPT などの外部 AI に読ませる場合も、この構成を前提にして、担当ごとの結果、メモ、判断理由、未解決事項を分けて扱う。

HOUHI リポジトリ自体を開発・保守するための仮想開発チームは、[仮想開発チーム構成.md](%E4%BB%AE%E6%83%B3%E9%96%8B%E7%99%BA%E3%83%81%E3%83%BC%E3%83%A0%E6%A7%8B%E6%88%90.md) を参照する。

## 基本指示

ユーザーが「この訴訟フォルダで仮想チームを結成して」「この訴訟フォルダでAIエージェントによる仮想チームを結成して」「法匪で整理して」「この訴訟フォルダを整理して」など、チーム作業又はフォルダ整理を依頼している場合は、次の体制を前提にする。

- 事件フォルダには、チームのための `00-訴訟管理/` フォルダを置く。
- `00-訴訟管理/` の中に、仮想チームのメンバーごとのフォルダを作る。
- 各メンバーの結果、メモ、判断理由、確認事項は Markdown として保存する前提で整理する。
- 必要に応じて各メンバーのフォルダに `AGENTS.override.md` を置き、その担当領域での追加指示を記録する。
- 裁判所に提出する書面や、人間が読む提出資料そのものは、`00-訴訟管理/` ではなく該当する日付フォルダに置く。

## フォルダ例

```text
00-訴訟管理/
├─ 01-ボス弁護士/
│  └─ AGENTS.override.md
├─ 02-整理係/
│  └─ AGENTS.override.md
├─ 03-調査係/
│  └─ AGENTS.override.md
├─ 04-起案係/
│  └─ AGENTS.override.md
├─ 05-レビュー係/
│  └─ AGENTS.override.md
└─ 06-後処理係/
   └─ AGENTS.override.md
```

## 実フォルダで作業する場合のメンバー

コーディングエージェントが実際の訴訟フォルダを開いて作業する場合は、OCR、文書分割、フォルダ振り分けが必要になることがある。そのため、次のメンバー構成を基本とする。

| メンバー | 役割 |
| :--- | :--- |
| ボス弁護士 | チームの統轄者。作業方針、優先順位、提出方針、各担当間の矛盾解消を管理する。 |
| 整理係 | 書類前処理として、OCR、文書ごとの分割・結合、必要なフォルダの作成、日付フォルダ・当事者フォルダ・号証フォルダへの振り分けを実行する。ファイルの移動・改名は、ユーザーが明示的に承認した範囲で行う。 |
| 調査係 | 前処理された書類や証拠を読み、争点、要調査事項、不足資料、確認事項をまとめる。 |
| 起案係 | 判例や法令を調査しつつ、訴状、準備書面、反論書、証拠説明書などの各書面を起案する。 |
| レビュー係 | 作成済み書類に矛盾、重複、根拠不足、重大な瑕疵、Markdown体裁の乱れがないか確認する。 |
| 後処理係 | 実際に提出する書類や証拠の PDF を作成し、ユーザーに結果と現実世界でやるべきアクションを提示する。 |

## 実フォルダで使うツール

- OCR、OCR Markdown の作成、PDF・画像・Word 等からの文書分割、文書結合は [`mimi-ocr`](https://github.com/mimidesunya/mimi-ocr) を使う。`mimi-ocr` が使えない場合、整理係は作業を進めず、ユーザーに `mimi-ocr` のセットアップを促す。
- 外部 AI OCR を使う可能性がある場合は、資料内容が外部 AI provider に送信され得ることを説明し、ユーザーの明示承認を得てから実行する。
- 裁判所提出用 PDF の作成、号証スタンプ、証拠 PDF の結合、FAX 向け PDF 化などは [`HOUHI`](https://github.com/mimidesunya/houhi) を使う。HOUHI が使えない場合、後処理係は作業を進めず、ユーザーに HOUHI のセットアップを促す。
- ChatGPT などの Chat AI だけでは、ローカルファイルの OCR、分割・結合、フォルダ作成、PDF 作成、号証スタンプは実行できない。Chat AI に渡す場合は、Markdown の作成、整理、レビュー、手順提示までを担当させる。

## `AGENTS.override.md` の扱い

各メンバーのフォルダには、必要に応じて `AGENTS.override.md` を置く。`AGENTS.override.md` には、その担当者の観点、成果物の保存先、禁止事項、確認すべき入力資料を書く。

`AGENTS.override.md` は上位の `AGENTS.md` を補足するためのものであり、安全ルール、原本保護、外部送信の承認要件、事実不明時の `【要確認】` 表示を弱めるものとして扱わない。

## AIアーカイブで使う場合

AI アーカイブを ChatGPT などの外部 AI に渡す場合、そのアーカイブは HOUHI により整理済みの資料であることを前提にする。OCR、文書ごとの分割・結合、フォルダ作成、フォルダ振り分けは完了済み又は別工程で扱うため、AI アーカイブ上の仮想チームには `整理係` を置かない。

Chat AI が担当できるのは Markdown の作成、整理、レビュー、手順提示までである。裁判所提出用 PDF の作成、号証スタンプ、証拠 PDF の結合、FAX 向け PDF 化は、Chat AI の外で [`HOUHI`](https://github.com/mimidesunya/houhi) により行う。ユーザー環境に HOUHI がない場合は、HOUHI のセットアップを促す。

AI アーカイブを読むだけの場合は、実際のフォルダ作成やファイル保存はできないことがある。その場合でも、次のメンバーごとに結果を分けて提示する。

| メンバー | 役割 |
| :--- | :--- |
| ボス弁護士 | チームの統轄者。読み取り方針、優先順位、回答方針、各担当間の矛盾解消を管理する。 |
| 調査係 | アーカイブ内の書類や証拠を読み、争点、要調査事項、不足資料、確認事項をまとめる。 |
| 起案係 | アーカイブ内資料と同梱指示を参照しつつ、各書面の原案や反論案を起案する。 |
| レビュー係 | 作成済みの分析や書面案に矛盾、重複、根拠不足、重大な瑕疵がないか確認する。 |
| 後処理係 | PDF 作成以外の後処理を担当する。Markdown 最終案、提出物一覧、ファイル名案、HOUHI で PDF 作成・号証スタンプすべき対象、現実世界でやるべき提出・確認・印刷などのアクションを示す。 |

- 保存すべき Markdown ファイル名
- 記載内容
- 次に AI エージェント又はユーザーが実行すべき操作
